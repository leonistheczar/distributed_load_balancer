## Appendix A - Glossary (Audience Friendly)
- **Load Balancer:** A controller that decides which backend node should handle each incoming request.
- **Node:** A simulated backend server that processes assigned requests.
- **Round Robin (RR):** Sends requests to nodes in fixed rotation order.
- **Weighted Round Robin (WRR):** Like RR, but higher-weight nodes receive more traffic.
- **Least Connections (LC):** Sends new request to the node currently handling the fewest active requests.
- **IP Hash:** Routes same client hash consistently to the same node (session affinity style).
- **Request Weight:** Proxy for request heaviness (e.g., image < page < heavy API/download).
- **Queue Capacity:** Maximum in-flight requests allowed per node before backpressure logic triggers.
- **Backpressure:** Behavior when system is near capacity; requests may be rerouted or dropped.
- **Reroute:** Assigning a request to another healthy node because selected node is saturated/unavailable.
- **Drop Rate:** Percentage of dispatched requests not completed due to capacity constraints.
- **Failover:** Redirecting traffic when a node becomes unhealthy.
- **p50 / p95 / p99:** Latency percentiles (50th, 95th, 99th). p99 reflects tail latency.
- **Imbalance Score:** Standard deviation of per-node request counts; lower is better load distribution.
- **Cache Hit Rate:** Ratio of requests found in a node's local cache model.

## Appendix B - How to Read the Results Quickly
- Start with `benchmark_summary_*.txt`:
  - Check **Winner (lowest p99 latency)**.
  - Check **Best load balance**.
  - Check **Drops** for congestion impact.
- Open `overview.html`:
  - See compact table + bar visual comparison.
- Open `nodes.html`:
  - Inspect per-node skew (requests, error rate, latency spread).
- Use JSON only for deep analysis:
  - `queue_wait_*` vs `service_latency_*` helps explain whether slowdown is queueing or service-time bound.

## Appendix C - Suggested Q&A Talking Points
- **Why simulation, not real servers?**
  - Controlled, reproducible benchmarking across algorithms on identical workload.
- **Why this dataset?**
  - Real-world e-commerce access logs with bots, burstiness, and URL diversity.
- **Why p99 matters most?**
  - User experience is often impacted by tail latency, not average latency.
- **Why can LC win balance but not always p99?**
  - Queue caps, reroute behavior, and request-weight distribution can change tail outcomes.
- **What does queue capacity demonstrate?**
  - Realistic saturation effects: backpressure, drops, and throughput/latency trade-offs.
